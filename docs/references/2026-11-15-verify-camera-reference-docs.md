## Additions (applied)

- `enableTorch(false)` does not restore LLB.
- `FLASH_MODE_SCREEN` needs 1.4.0+.
- `ImageCaptureException` also has `ERROR_UNKNOWN`, `ERROR_CAMERA_CLOSED`.
- `getSystemService(Class)` is API 23+.
- Legacy list `createCaptureSession` deprecated API 30; `openCamera` can throw IAE.
- `FocusMeteringAction.Builder(point, FLAG_AF or FLAG_AE)` excludes AWB (1-arg default = all three).
- `getExtensionEnabledCameraSelector` deprecated 1.7.0-rc02 → `ExtensionSessionConfig`.
- `setOutputFormat` experimental in 1.4.x, stable from 1.5.0-alpha04.
- Interop deprecation announced 1.7.0-alpha03; reference stamps rc02.
- `Image.timestamp == SENSOR_TIMESTAMP` holds for plain RAW reader; timestamp base (API 33) can change it.

#### Operationally important facts omitted by lines 355-505

1. PRIVATE ImageAnalysis format, getImageAnalysisCapabilities, CameraController.setAutoRotationEnabled, CameraControl.applyInteropAsync, setSessionConfig (reference marker): all "Added in 1.7.0-rc02". Stable 1.6.2 does not have them.
2. Camera2CameraControl, Camera2Interop.Extender, Camera2CameraInfo are Deprecated in 1.7.0-rc02; replacements: CameraControl.applyCamera2Interop/Async, UseCase.Builder.camera2Interop, SessionConfig.Builder.camera2Interop, CameraInfo extension properties.
3. Interop options override CameraX internals and can break CameraControl features (e.g. FLASH_MODE vs torch; 3A). applyCamera2Interop overwrites SessionConfigInterop options. Do not call close/abortCaptures/stopRepeating/setRepeatingRequest/capture on callback sessions.
4. ImageProxy must be closed: not closing "will cause future images to be stalled or dropped". KEEP_ONLY_LATEST is default; BLOCK_PRODUCER can stall Preview too; default queue depth 6.
5. ImageAnalysis default resolution 640x480; setOutputImageRotationEnabled costs ~10-15 ms for 640x480 on mid-range device, API 23+, default off; ImageProxy rotation then 0.
6. LIMITED+ devices can give ImageAnalysis RECORD size with Preview+ImageCapture only if both ImageCapture and ImageAnalysis request RECORD; ImageCapture then loses MAXIMUM size.
7. NV21 output: ImageProxy is YUV_420_888 laid out as NV21; ImageProxy.getImage() may differ in planes/size.
8. CameraControl: every call returns ListenableFuture; operations are rejected when no use cases bound or camera closed; supersession gives OperationCanceledException. Torch and low-light boost are mutually exclusive ("last setting wins"); low-light boost disabled above 30 FPS, requires Android 15+; enableTorch with no flash unit fails.
9. startFocusAndMetering: points beyond device support truncated; if none supported, future fails (IAE) immediately; 3A locks persist until cancelFocusAndMetering or auto-cancel.
10. CameraController: Preview always enabled and cannot be disabled; VideoCapture off by default; changing configuration after bind causes reconfiguration latency (set before bindToLifecycle); setSessionConfig throws IAE for invalid/unsupported use case combos; takePicture(file) crops to PreviewView aspect ratio.
11. Camera2 stream tables: RAW rows apply to RAW-capable FULL/LIMITED devices; unlisted combinations testable only via isSessionConfigurationSupported.
12. Stream sharing for Preview+VideoCapture on FULL-or-lower devices costs processing/battery.
13. AndroidX stage rules: beta cannot depend on alpha libraries; RC deps must be rc/stable; alpha is "functionally stable, may not be feature-complete".
